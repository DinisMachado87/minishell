	Redirects:
		- <:
			- It seems to output the content of the file that comes after to stdin. When there is multiple redirects, unless their output has not been "consumed"
				by a command, the latter one overrides the prior one. The problem is, when i redirect the output of the file to the general stdin, it will be
				consumed by the TTY (Terminal). I wonder if that is also the case for our minishell, but that I can only test with the whole chain working.
			- < test.txt cat
				file content
			- cat < test.txt
				file content
			- cat < test.txt test2.txt
				file2 content
			- < test.txt test2.txt cat
				bash: test2.txt: command not found
			- cat test.txt test2.txt
				file content
				file2 content
		- >:
			- Redirects the prior stdout into the following file, overriding its current content
			- echo "file content" > test.txt
			minishell/src$ cat test.txt
			minishell/src$ echo "Hello" > test.txt
			minishell/src$ cat test.txt
			Hello
			minishell/src$ cd .. > test.txt
			minishell$ cd src/
			minishell/src$ cat test.txt
			minishell/src$
		- >>:
			- Same but in append mode
		- <<:
			- Heredoc. A EOF is defined and all the following content up until the EOF is entered again will be redirected to stdin
